# Codebase Audit — 2026-08-06

A full-project audit of the backend (FastAPI / Python, ~35k LOC) and frontend
(Vue 3 + TypeScript, 109 components / ~110 stores & modules) hunting for
correctness bugs, robustness gaps, security weaknesses and performance issues.

The codebase was swept subsystem-by-subsystem (G-code/motion pipeline,
converters & algorithms, hardware I/O & queue & persistence, HTTP/API &
security, frontend stores, frontend components). Every candidate finding was
verified against the code and its tests before being accepted; several were
reproduced with throwaway scripts. False positives and already-correct
behaviour were discarded.

## Verdict

The architecture is clean and the project is clearly well-maintained (prior
audits show). Baselines were green before this pass (backend 1249 tests,
frontend 1040 tests; ruff / mypy --strict / eslint / vue-tsc all clean). No
architectural defects. The defects found were subtle: a datetime-format
mismatch that silently disabled crash-recovery, a coordinate-space bug that put
DXF text thousands× off-page, a modal-feedrate gap in the resume path, and an
ack-wait loop that could busy-spin a stuck controller forever — plus a spread
of medium/low correctness, robustness and UX issues.

**This pass fixed 19 issues (8 with new regression tests).** All suites remain
green: **backend 1255 passed / 1 skipped, frontend 1042 passed**, ruff / mypy
--strict / eslint / vue-tsc / prettier clean, OpenAPI + manifest + contract
drift checks clean.

## Fixed in this pass

### Backend — correctness (high severity)

| # | Area | Finding | Fix |
| --- | --- | --- | --- |
| 1 | `queue.py` `claim_next_queued` / `reclaim_expired_leases` | The atomic claim wrote `lease_until` via raw SQL as `.isoformat()` (`…T…+00:00`), but the reclaim query compared it through the ORM's SQLite `DateTime` format (`… …`, no offset). SQLite compares datetimes as **text**, and `'T'` (0x54) sorts after `' '` (0x20), so a same-day expired lease never satisfied `lease_until < now` → a crashed worker's run was **never** parked to PAUSED and never recovered. Reproduced. | Type the `lease`/`now` bind params as `DateTime` and pass `datetime` objects so SQLAlchemy serialises them identically to every ORM write. Regression test stamps the lease through the **real** claim path (the old test seeded via the ORM, hiding the bug). |
| 2 | `converters/dxf.py` + `core/dxf_postprocess.py` | With `hershey_text=True`, the Hershey text overlay is built in ezdxf's ~1 000 000-unit viewBox space, but `postprocess_dxf_svg` rebases the document to mm and scales the colour groups — while the overlay was spliced in **without** the transform. Text landed ~20 000× off-page, blowing up the bbox so real geometry collapsed to a speck. Verified: a 50×30 mm drawing put text at ~435 000 units. | Expose the rebase transform (`mm_rebase_transform`) and stamp it on the overlay group (added an optional `transform=` to `render_placed_spans`). Regression test asserts the text lands inside the mm viewBox. |
| 3 | `core/resume.py` | The resume replay recovered units / position / pen state but **not** the modal feedrate. The travel-back move emits the *travel* feed, so a resumed program that keeps drawing without restating `F` (legal — feed is modal; common in uploaded/CAM G-code) finished the interrupted path at travel speed (~24× too fast → skipped steps / ruined strokes). OmniPlot's own generated G-code is immune (explicit `F` per move). | Track the last `F` in the replay; re-emit it (in the job's units) before the remainder — but only when the remainder actually inherits the modal feed, so generated programs stay byte-identical. Two regression tests (positive + no-op). |

### Backend — robustness (high / medium)

| # | Area | Finding | Fix |
| --- | --- | --- | --- |
| 4 | `hardware/streamer.py` `_wait_ok` + `hardware/controller.py` `_send_immediate` | The ack wait used a *per-read* silence timeout, not an operation deadline. A closed link whose reads return `""` instantly (EOF) — or a controller emitting steady non-`ok` chatter — never tripped the timeout and **busy-spun forever at ~100% CPU**, wedging the queue worker. | Bound the whole wait by a monotonic deadline and treat a confirmed EOF (`at_eof()`, added to the transport) as terminal. Regression test hangs (killed at 40 s) without the fix, passes in <1 s with it. |
| 5 | `timelapse.py` `_loop` | On a frame-write `OSError` (disk full), the capture loop finalised the session but left `self._session` set, so `delete()` refused the id forever and the frames sat unremovable — exactly when the operator needs to free space. | Release `self._session` in the `except OSError` branch (leaving `_task` untouched to avoid racing a concurrent `stop()`). Regression test. |
| 6 | `api/plotter.py` `/ws/plotter` | The progress WS blocked on `queue.get()` with no keepalive, so while the plotter was idle a dead-but-unclosed socket was never noticed and leaked its subscriber + task until the next print. | Wrap the wait in a `_WS_KEEPALIVE_S` timeout that re-sends the current status (mirrors `/ws/queue`), so a dead socket is detected and unsubscribed promptly. |
| 7 | `api/analyze.py` `/document/analyze` | Read the whole upload into RAM (`await file.read()`) **before** the 50 MB check, so a multi-GB body was fully materialised before the 413 → OOM on a Pi. | Use the shared streaming `read_upload_safely`, which aborts mid-read at the cap. |

## Recommended follow-ups (not fixed here)

These are real but were left for a deliberate decision because the fix changes
operator-facing behaviour (needs a config choice), requires a schema migration,
or carries more regression risk than its severity warrants. Each is described
with a concrete remediation.

### Security hardening

- **DNS-rebinding (high).** In open mode (the default loopback install, no
  `OMNIPLOT_API_KEY`) the only cross-site-write defence is the
  `Origin == Host` check in `main.py`, which a DNS rebind defeats (both headers
  are attacker-controlled after rebinding). There is no `Host` allowlist.
  *Remediation:* add `TrustedHostMiddleware` (or a `Host` check) against an
  allowlist derived from loopback + the bound host + `OMNIPLOT_CORS_ORIGINS`,
  with an `OMNIPLOT_TRUSTED_HOSTS` override. Left unfixed to avoid a default
  that breaks LAN access via custom hostnames / mDNS — needs the operator to
  choose the allowlist.

- **Camera-URL SSRF is TOCTOU (medium).** `timelapse.validate_camera_url`
  resolves + vets the host, then `grab_jpeg` re-resolves via `urllib` at connect
  time, so a short-TTL/rebinding record can pass validation then connect to
  `169.254.169.254` / loopback. *Remediation:* resolve once and connect to the
  vetted IP literal (pin DNS; set Host/SNI to the original name), re-validating
  redirect hops the same way.

- **No pre-auth body-size cap (medium).** In locked mode FastAPI reads/parses
  the whole body before the route's API-key dependency runs, so an
  unauthenticated oversized body is fully buffered before the 401.
  *Remediation:* an outermost middleware that rejects over-limit `Content-Length`
  before routing (cap derived from `OMNIPLOT_MAX_UPLOAD_MB` + margin).

- **XML/SVG DOCTYPE not rejected (low, mostly mitigated).** Uploaded SVG is
  parsed with stdlib `ElementTree` and no DOCTYPE rejection; billion-laughs is
  currently capped only by the runtime's libexpat. *Remediation:* reject
  `<!DOCTYPE>`/entity declarations before parse (note: some legitimate SVGs
  carry a benign DOCTYPE, so reject entity **declarations** specifically rather
  than every DOCTYPE).

- **Internal exception text in error envelopes (low).** Several handlers put raw
  `str(exc)` into `HTTPException.detail`, which can surface temp paths / library
  internals to the client. *Remediation:* log server-side with the request id
  and return a generic client message for converter/generation 422/500s.

### Other

- **`PrintRun` history unbounded + no index (low).** Terminal runs are never
  pruned and the history query orders by `created_at` with no index → full scan
  as history grows. *Remediation:* add an index on `created_at` (needs a schema
  migration for existing DBs) and a retention/prune policy.

- **`core/arcs.py` `fit_arcs` is O(m²) per co-circular span (low).** Each greedy
  extension re-fits and re-checks the whole run. Only a pathological single long
  smooth polyline is affected (vpype quantisation bounds `m` in practice).
  *Remediation:* extend incrementally / cap the arc-run length.

- **`DualRangeSlider` thumbs can coincide (low, plausible).** When both endpoints
  pin to the max the min thumb sits under the max thumb and can't be grabbed.
  *Remediation:* raise the z-index of the pointer-nearest input or enforce a
  minimum gap.
