# Codebase Audit — 2026-08-06

A full-project audit of the backend (FastAPI / Python, ~35k LOC) and frontend
(Vue 3 + TypeScript, 109 components / ~110 stores & modules) hunting for
correctness bugs, robustness gaps, security weaknesses and performance issues.

The codebase was swept subsystem-by-subsystem (G-code/motion pipeline,
converters & algorithms, hardware I/O & queue & persistence, HTTP/API &
security, frontend stores, frontend components). Every candidate finding was
verified against the code and its tests before being accepted; several were
reproduced with throwaway scripts. False positives and already-correct
behaviour were discarded.

## Verdict

The architecture is clean and the project is clearly well-maintained (prior
audits show). Baselines were green before this pass (backend 1249 tests,
frontend 1040 tests; ruff / mypy --strict / eslint / vue-tsc all clean). No
architectural defects. The defects found were subtle: a datetime-format
mismatch that silently disabled crash-recovery, a coordinate-space bug that put
DXF text thousands× off-page, a modal-feedrate gap in the resume path, and an
ack-wait loop that could busy-spin a stuck controller forever — plus a spread
of medium/low correctness, robustness and UX issues.

**This pass fixed 19 issues (8 with new regression tests).** All suites remain
green: **backend 1255 passed / 1 skipped, frontend 1042 passed**, ruff / mypy
--strict / eslint / vue-tsc / prettier clean, OpenAPI + manifest + contract
drift checks clean.

### Backend — correctness (high severity)

| # | Area | Finding | Fix |
| --- | --- | --- | --- |
| 1 | `queue.py` `claim_next_queued` / `reclaim_expired_leases` | The atomic claim wrote `lease_until` via raw SQL as `.isoformat()` (`…T…+00:00`), but the reclaim query compared it through the ORM's SQLite `DateTime` format (`… …`, no offset). SQLite compares datetimes as **text**, and `'T'` (0x54) sorts after `' '` (0x20), so a same-day expired lease never satisfied `lease_until < now` → a crashed worker's run was **never** parked to PAUSED and never recovered. | 2 | `converters/dxf.py` + `core/dxf_postprocess.py` | With `hershey_text=True`, the Hershey text overlay is built in ezdxf's ~1 000 000-unit viewBox space, but `postprocess_dxf_svg` rebases the document to mm and scales the colour groups — while the overlay was spliced in **without** the transform. Verified: a 50×30 mm drawing put text at ~435 000 units. | Expose the rebase transform (`mm_rebase_transform`) and stamp it on the overlay group (added an optional `transform=` to `render_placed_spans`). ## Recommended follow-ups (not fixed here)

These are real but were left for a deliberate decision because the fix changes
operator-facing behaviour (needs a config choice), requires a schema migration,
or carries more regression risk than its severity warrants. Each is described
with a concrete remediation.

### Security hardening

- **DNS-rebinding (high).** In open mode (the default loopback install, no
  `OMNIPLOT_API_KEY`) the only cross-site-write defence is the
  `Origin == Host` check in `main.py`, which a DNS rebind defeats (both headers
  are attacker-controlled after rebinding). There is no `Host` allowlist.
  *Remediation:* add `TrustedHostMiddleware` (or a `Host` check) against an
  allowlist derived from loopback + the bound host + `OMNIPLOT_CORS_ORIGINS`,
  with an `OMNIPLOT_TRUSTED_HOSTS` override. Left unfixed to avoid a default
  that breaks LAN access via custom hostnames / mDNS — needs the operator to
  choose the allowlist.

- **Camera-URL SSRF is TOCTOU (medium).** `timelapse.validate_camera_url`
  resolves + vets the host, then `grab_jpeg` re-resolves via `urllib` at connect
  time, so a short-TTL/rebinding record can pass validation then connect to
  `169.254.169.254` / loopback. *Remediation:* resolve once and connect to the
  vetted IP literal (pin DNS; set Host/SNI to the original name), re-validating
  redirect hops the same way.

- **No pre-auth body-size cap (medium).** In locked mode FastAPI reads/parses
  the whole body before the route's API-key dependency runs, so an
  unauthenticated oversized body is fully buffered before the 401.
  *Remediation:* an outermost middleware that rejects over-limit `Content-Length`
  before routing (cap derived from `OMNIPLOT_MAX_UPLOAD_MB` + margin).

- **XML/SVG DOCTYPE not rejected (low, mostly mitigated).** Uploaded SVG is
  parsed with stdlib `ElementTree` and no DOCTYPE rejection; billion-laughs is
  currently capped only by the runtime's libexpat. *Remediation:* reject
  `<!DOCTYPE>`/entity declarations before parse (note: some legitimate SVGs
  carry a benign DOCTYPE, so reject entity **declarations** specifically rather
  than every DOCTYPE).

- **Internal exception text in error envelopes (low).** Several handlers put raw
  `str(exc)` into `HTTPException.detail`, which can surface temp paths / library
  internals to the client. *Remediation:* log server-side with the request id
  and return a generic client message for converter/generation 422/500s.

### Other

- **`PrintRun` history unbounded + no index (low).** Terminal runs are never
  pruned and the history query orders by `created_at` with no index → full scan
  as history grows. *Remediation:* add an index on `created_at` (needs a schema
  migration for existing DBs) and a retention/prune policy.

- **`core/arcs.py` `fit_arcs` is O(m²) per co-circular span (low).** Each greedy
  extension re-fits and re-checks the whole run. Only a pathological single long
  smooth polyline is affected (vpype quantisation bounds `m` in practice).
  *Remediation:* extend incrementally / cap the arc-run length.

- **`DualRangeSlider` thumbs can coincide (low, plausible).** When both endpoints
  pin to the max the min thumb sits under the max thumb and can't be grabbed.
  *Remediation:* raise the z-index of the pointer-nearest input or enforce a
  minimum gap.

## Recommended follow-ups from the second wave (not fixed)

Left for a deliberate decision — a systematic refactor, rotation-math work, or
tuning sensitive to real-world sizing:

- **Editor numeric inputs — a *class* of unclamped fields (medium).** Beyond the
  fixed `num_bands` / layer-speed cases, `PostProcessCard` (`min_region_pixels`,
  `merge_delta_e`, `background_luminance`), `TypographyCard` (7 fields),
  `AlgoParamsForm` (generic number options), and `ProfilePenFields` (live pen
  count) use bare `v-model.number` / unclamped `@input`. A cleared field ships
  `''`→NaN (broken preview / 422) or an out-of-range value. *Remediation:* a
  shared clamp helper bound as `:value` + `@change` across the editor cards
  (the `SegmentationCountCard`/`LevelsCard` pattern).
- **PDF rotated pages (medium).** Hershey text re-render (`converters/pdf.py`)
  and the block analyzer (`converters/pdf_blocks.py`) use un-rotated glyph/block
  coordinates while the SVG/page dims are rotated, so on a `/Rotate 90` page the
  overlay/blocks land far off. *Remediation:* apply `page.rotation_matrix` to
  the origins/rects (and skip/warn for 90°/270° where glyph run-direction can't
  be expressed).
- **Hatch-line DoS (low-medium).** `_hatch_lines_for_bbox` has no upper cap; a
  shape with a huge bbox (coordinates outside the media box) generates millions
  of `<path>`s. *Remediation:* clamp the shape bbox to the page / bail above a
  line-count ceiling.
- **Optimizer skipped for a multi-subpath single `<path>` (medium).**
  `toolpath.py`'s early-exit counts SVG *elements*, not `M`-delimited subpaths,
  so single-`<path>` art (incl. single-line Hershey text) skips linesort/2-opt
  and reports `pen_up=0`. *Remediation:* gate on actual subpath count.
- **Preflight/G-code parity on empty-bounds layers (low-medium).** Preflight
  counts pen changes for labeled-but-empty layers that `generate_gcode` skips
  under `if not bounds.empty`. *Remediation:* share one guarded loop.
- **SSE stream thread starvation (low-medium).** Each preview/rerender stream
  parks two default-executor threads; a few concurrent streams can starve
  `run_in_threadpool`. *Remediation:* bridge via `call_soon_threadsafe` onto an
  `asyncio.Queue`.
- **Tip-detect wrong-blob confidence (medium).** A shadow/glare larger than the
  tip is selected and can pass the confidence gate, storing a wrong calibration
  baseline. *Remediation:* an absolute size/plausibility check (kept out of this
  pass to avoid mis-tuning real-tip confidence).
- **Lower priority:** user-preset `options` payload not size-bounded
  (`presets.py`); `average_tips` preview marker drawn at the closest sample's
  tip rather than the median; `HersheyRenderer._break_long_word` O(L²);
  `useEditorInkSwatches` coverage weights applied without a staleness token;
  preview palette `coverage` hard-coded 0.0; `curl|bash` installers without a
  checksum and the shipped `axios` advisory (the "6 npm highs" are dev-only);
  perf scripts' predictable `/tmp` DB paths.

> **Note:** `test_vectorize_embedded_images_creates_labeled_group` is
> order-dependent — it passes in the full suite but fails in isolation (relies
> on potrace state another test file sets up first). Pre-existing; a test-hygiene
> cleanup, not a product bug.

# Follow-up fixes (continued)

Working through the recommended follow-ups above, the following were fixed
(backend 1261 passed / 1 skipped, frontend 1043 passed; all lint/type/drift
checks clean):

- **Editor unclamped-input class — done.** `PostProcessCard` (3 fields),
  `TypographyCard` (7 fields), `AlgoParamsForm` (generic number/integer
  options), and `ProfilePenFields` (live pen-count render) now bind
  `:value` + `@change` with a clamp to each field's schema range, so a cleared
  field can't ship `''`→NaN and out-of-range values are bounded. Regression
  test on `PostProcessCard`.
- **PDF rotated pages — done.** Hershey text origins and block/image bboxes are
  mapped through `page.rotation_matrix` (identity at 0°), so a `/Rotate` page's
  overlay and BlockMapCard regions land correctly; a rotated page also warns
  that the horizontal renderer can't rotate the text-run direction. Regression
  tests for both.
- **Optimizer multi-subpath early-exit — done.** `_path_count` now counts
  `M`/`m` subpaths, so single-`<path>` art (single-line Hershey text, icons)
  is optimized instead of shipping in raw order with a false zero pen-up.
- **Preflight ↔ G-code parity on empty-bounds layers — done.** Preflight skips
  the per-layer loop when `bounds.empty`, matching `generate_gcode`.
- **Hatch-line DoS cap — done.** Hatch spacing widens past `_MAX_HATCH_LINES`
  so a huge/adversarial bbox can't emit millions of `<path>`s.
- **SSE stream thread starvation — done.** `/preview-stream` and `/rerender`
  bridge the worker thread onto an `asyncio.Queue` via `call_soon_threadsafe`
  instead of parking a second pool thread on a blocking `queue.get`, so a few
  concurrent streams no longer starve `run_in_threadpool` on a Pi.
- **`useEditorInkSwatches` coverage-weight staleness — done.** Monotonic token
  so a slower earlier raster can't clobber the fresh coverage map.
- **User-preset `options` size bound — done.** `save_user_preset` caps the
  serialized payload (32 KiB → 422), honouring the store's documented invariant.
- **Shipped `axios` advisory — done.** Bumped 1.16.1 → 1.19.0 (within `^1`);
  the other npm "highs" are dev/build-only.

Still open, deliberately left to the maintainer (each would need a tuning /
trust / churn decision that outweighs its value):

- **tip-detect wrong-blob confidence** — needs an absolute tip-area/aspect
  threshold tuned to the deployment's camera + pen tips (test tips are ~1 mm²,
  shadows ~56 mm², but a wide marker tip can be ~20 mm²); a guessed threshold
  could reject legitimate calibration, so it's a domain decision.
- **`average_tips` preview marker vs median** — low; would require threading the
  raw sample frames through `average_tips` (extra memory) to redraw the marker
  at the aggregated median rather than the closest sample's own tip.
- **`HersheyRenderer._break_long_word` O(L²)** — only bites on a huge page *and*
  a very long no-space token; an incremental fix shifts the break metric from
  ink-extent to advance and risks changing wrap points.
- **preview palette `coverage` hard-coded 0.0** — a dead contract field; the UI
  computes its own coverage (`coverageWeights`) and never reads this one, so it
  is misleading-but-unused. Dropping it is a schema/types change with more churn
  than value.
- **`curl|bash` installer trust assumption** — pinning the NodeSource/uv
  installers to a checksum (or a signed apt keyring) is the right hardening but
  changes the install UX; documented as a trust assumption for now.
- **perf scripts' `/tmp` DB paths** — dev/CI-only; the predictable-path symlink
  risk needs a shared multi-user host, which CI runners are not.
